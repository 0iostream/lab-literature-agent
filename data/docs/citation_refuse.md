# 引用格式、门禁与拒答（学习笔记）

## 可验证引用长什么样

约定格式如 [doc_id#chunk]，例如 [react#0]。doc_id 对应文献文件，数字为切分序号。答案里抽出的 id 必须能在 DocumentStore.get 查到，否则视为非法引用。只写「据某论文」而没有库内 id，在本项目的评测标准下不算合法引用。

## 引用门禁何时触发

当本轮调用过检索类工具时，最终答案应满足：至少有一个合法引用，或明确拒答。门禁失败可提示模型重试一次，要求只用真实 chunk_id；仍失败则系统侧收尾为证据不足，而不是放行幻觉引用。

## 拒答话术

拒答应清楚表达「不知道 / 检索不到 / 证据不足」，避免用模糊的「不确定」单独作为唯一标记——讨论「是否需要检索并不确定」时可能误伤。评测用的拒答词表要与产品文案一起维护。

## 假引用与堆引用

假引用：捏造不存在的 id。堆引用：拒答或闲聊时贴上一串无关 chunk，看起来很「有依据」。两者都应用门禁或规则抑制。人工抽查忠实度时，重点看句子是否真能由对应片段支持。

## 与传统学术引用的差别

学术论文引用指向外部出版物；本系统的 [doc#chunk] 指向本地可控语料中的片段，目的是让评测与调试可复现。换语料或重切分后，旧 id 可能失效，需要重新 ingest 并更新金标。

## 拒答后还要不要引用

证据不足时，优先明确拒答；若仍附带检索到的无关片段引用，会误导用户以为有依据。门禁与产品文案应约定：拒答默认不堆引用，或只允许引用「说明库中无相关」的元说明（若有）。

## 正则抽取

从答案中用正则抽出 [doc#数字] 时，要允许 doc_id 含下划线等字符，并忽略 markdown 其它方括号。抽出后必须二次查库，不能只靠格式合法。


## 补充：实践中的取舍

实习项目的文献库贵在「可复现、可评测、能讲清方法」，不在于堆到百万字。把同一套切分、检索、引用与拒答流程跑通，并保存带配置的评测报告，比盲目扩库更有说服力。扩库时优先增加与 Agent / RAG / 评测相关的主题段落，避免粘贴无关长文稀释检索信号。

当文档变长后，注意：chunk 数量上升会拉长向量编码时间；金标里的 chunk_id 若仍指向旧语义，需要抽查 get()；简历上的 Recall 数字应在扩库后重跑再写，不要沿用小库饱和指标假装通用。

调试建议：扩库前后各跑一遍检索金标与端到端子集，对比误检索与延迟。若同义改写变好但专有名词变差，检查混合融合是否仍保留词法通路。若延迟明显上升，记录是 embedding、rerank 还是多轮 LLM 占主导。

对面试官可这样表述：语料为可控本地笔记，规模用于验证 Agent 循环与评测体系；方法（混合检索、引用门禁、Workflow 对照）可迁移到更大文献库，但当前数字对应本库配置。

### 引用拒答扩写要点
库越大，假引用与堆无关引用的诱惑越强。门禁与人工忠实度抽查不能省。拒答文案与评测词表保持一致。
