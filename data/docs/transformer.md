# Transformer 与注意力机制（学习笔记）

Transformer 用自注意力代替循环网络，让序列中任意两个位置可以直接交互。

## Scaled Dot-Product Attention

对每个位置构造 Query、Key、Value。相似度是 Query 与 Key 的点积，再除以 sqrt(d_k) 防止点积过大导致 softmax 过尖。得到的权重乘到 Value 上，就是该位置的输出。

多头注意力把 d_model 拆成多个子空间，让模型同时关注不同类型的关系，再拼回去并用线性层混合。

## 结构要点

- 残差连接：把子层输入加到输出上，缓解深层网络难训练。
- LayerNorm：在特征维上归一化；和 BatchNorm 不同，不依赖 batch 统计。
- FFN：两层全连接，先升维再降维，提供非线性。
- 位置编码：注意力本身没有顺序，必须把位置信息加进输入。

Encoder 负责编码输入，Decoder 在生成时用因果掩码，不能看见未来 token。GPT 一类模型主要使用 Decoder。

## 为什么常用 LayerNorm 而不是 BatchNorm

自然语言批次里序列长度差异大，BatchNorm 依赖 batch 维统计不稳定；LayerNorm 在每个样本的特征维上归一化，训练与推理行为更一致，因此 Transformer 里更常见。

## 位置编码常见做法

绝对位置编码把固定或可学习的位置向量加到 token 嵌入上。相对位置偏置则直接作用于注意力分数。无论哪一种，目的都是让模型区分「谁在前、谁在后」，否则纯注意力对置换不敏感。

## 和 RAG / Agent 的关系

Embedding 模型与生成模型都可以基于 Transformer。本地中文向量检索常用小型 encoder（例如 bge-small-zh）；生成侧则通过 Chat Completions 调用更大的 Decoder 模型。理解注意力有助于解释：为何长上下文仍可能「忽略」中间证据，以及为何要把检索片段截断到可控长度。

## Softmax 温度与生成

解码时的 temperature 控制采样随机性：越低越greedy、越稳，越高越多样也越易跑偏。文献问答与评测对照里，生成节点常用较低 temperature，减少同题多次运行的方差，便于比较 Workflow 与 Agent。

## KV Cache 与多轮成本

自回归生成时，已计算过的 Key/Value 可缓存，避免每步重算历史。Agent 多轮会把 Observation 不断追加进 messages，输入侧 token 随步数增长，费用和延迟都上升。因此要限制 max_steps、压缩轨迹摘要，并避免把无关历史塞进每次请求。

## 因果掩码

Decoder-only 模型用下三角掩码，使位置 i 只能看见 ≤ i 的 token。这保证训练与生成都是「从左到右」。理解这一点有助于区分：检索片段是作为已经可见的上下文提供的，模型并不会「先写答案再回头看文献」，除非你的 Agent 循环显式安排了先检索后生成的步骤。

## 双塔与交叉编码

双塔（bi-encoder）分别编码 query 与文档，适合大规模召回。交叉编码（cross-encoder）把两者拼在一起打分，更准更慢，适合对少量候选 rerank。混合检索流水线常是：双塔或词法召回 -> 交叉编码精排 -> 生成。

## 训练目标一瞥

句向量常用对比学习：让相关句对更近、无关句对更远。生成模型则在下一词预测或指令微调目标上训练。应用层 intern 不必复现预训练，但要能说清：你用的 embedding 模型大致属于哪一类、为何选小模型做本地检索。


## 补充：实践中的取舍

实习项目的文献库贵在「可复现、可评测、能讲清方法」，不在于堆到百万字。把同一套切分、检索、引用与拒答流程跑通，并保存带配置的评测报告，比盲目扩库更有说服力。扩库时优先增加与 Agent / RAG / 评测相关的主题段落，避免粘贴无关长文稀释检索信号。

当文档变长后，注意：chunk 数量上升会拉长向量编码时间；金标里的 chunk_id 若仍指向旧语义，需要抽查 get()；简历上的 Recall 数字应在扩库后重跑再写，不要沿用小库饱和指标假装通用。

调试建议：扩库前后各跑一遍检索金标与端到端子集，对比误检索与延迟。若同义改写变好但专有名词变差，检查混合融合是否仍保留词法通路。若延迟明显上升，记录是 embedding、rerank 还是多轮 LLM 占主导。

对面试官可这样表述：语料为可控本地笔记，规模用于验证 Agent 循环与评测体系；方法（混合检索、引用门禁、Workflow 对照）可迁移到更大文献库，但当前数字对应本库配置。

### Transformer 扩写要点
理解双塔召回与交叉编码重排，有助于解释延迟从毫秒级到秒级的跳变。生成侧温度、上下文长度与 Agent 步数共同决定成本；扩库不自动等于要换更大生成模型。
