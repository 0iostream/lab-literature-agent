# RAG 与 Agentic RAG

RAG（Retrieval-Augmented Generation）把外部文档检索结果塞进提示词，减轻参数记忆过时和幻觉。

## 传统 RAG

固定流水线：切分 → 向量化 → 取 top-k → 一次性生成。控制流在代码里。这是增强型问答，还不是 Agent。

切分过大：一个 chunk 混进多个主题，检索噪声高。切分过小：句子缺上下文。overlap 用来保住跨边界的句子。

## Agentic RAG

由模型决定：现在要不要搜、搜什么、要不要改写 query 再搜、要不要读某个 chunk。检索成为工具，而不是永远先搜再答。

适用：问题是否需要检索并不确定，或需要多跳（先搜 A 再根据 A 搜 B）。

## 引用

可靠系统应在答案中保留 chunk_id，例如 [rag#0]。没有检索命中时应该拒绝回答，而不是编造文献。

## 检索方式简述

- 词法检索：依赖关键词重叠，专有名词、公式符号友好，但对同义改写弱。
- 向量检索：用 embedding 比语义相似度，同义表达更稳，但对极短专有名词可能不如词法。
- 混合检索：常见做法是两路召回再用 RRF（Reciprocal Rank Fusion）合并排序，兼顾关键词与语义。
- 重排（rerank）：对混合后的候选做 cross-encoder 精排；小库上指标可能已饱和，但仍应报告延迟代价。

## Query 改写

当 search 返回 NO_HITS 时，可保留专有名词与数字，改写表述后再搜；不要一上来就改写，以免丢掉用户原词。改写本身也可做成工具，由 Agent 在观察 NO_HITS 后决定是否调用。

## 忠实度与引用率

合法引用率只说明答案里出现了库中真实存在的 chunk_id；不保证句子内容真被该片段支持。需要人工或自动抽查「答案是否可由引用片段推出」。评测报告应分开写这两类指标，避免把引用格式正确说成 faithfulness。

## 上下文如何塞检索结果

常见做法是把 top-k 片段格式化成「[chunk_id] + 正文」块，放进用户消息或独立 system 补充段。k 太小易漏证据，k 太大则噪声和费用上升，还可能触发「中间丢失」。Agentic 场景里，模型可先看短摘要列表，再对可疑 id 调用精读工具，而不是一次灌入全部长文。

## 索引更新

文档变更后必须重新切分与（如需要）重新编码 embedding，并落盘索引。若评测金标绑定了旧的 chunk_id，改切分参数或大改原文可能导致 id 错位，需要抽查 DocumentStore.get 与相关金标是否仍指向正确内容。

## 小库与大库的差别

教学用本地笔记库可以很快把 Recall 打满，这时对比实验更应关注延迟、步数、误检索与拒答行为。真实实验室文献库文档更长、噪声更多，混合检索与 rerank 的收益通常更明显，也更需要权限与脱敏策略。

## top-k 如何选

k 是召回宽度。过小：答案证据不在候选里，后面生成再强也救不回来。过大：噪声进入提示词，费用与「中间丢失」风险上升。实践上先固定一个 k 跑检索金标，看 Recall@k 曲线，再决定是否加大混合召回、用 rerank 收窄最终进入生成的条数。

## 元数据

除正文外，可为 chunk 保存来源路径、标题、更新时间。当前最小实现以 chunk_id 与正文为主；若将来按文档权限过滤，元数据会变成硬需求。评测与简历数字仍应基于实际实现，未做权限过滤就不要写。


## 补充：实践中的取舍

实习项目的文献库贵在「可复现、可评测、能讲清方法」，不在于堆到百万字。把同一套切分、检索、引用与拒答流程跑通，并保存带配置的评测报告，比盲目扩库更有说服力。扩库时优先增加与 Agent / RAG / 评测相关的主题段落，避免粘贴无关长文稀释检索信号。

当文档变长后，注意：chunk 数量上升会拉长向量编码时间；金标里的 chunk_id 若仍指向旧语义，需要抽查 get()；简历上的 Recall 数字应在扩库后重跑再写，不要沿用小库饱和指标假装通用。

调试建议：扩库前后各跑一遍检索金标与端到端子集，对比误检索与延迟。若同义改写变好但专有名词变差，检查混合融合是否仍保留词法通路。若延迟明显上升，记录是 embedding、rerank 还是多轮 LLM 占主导。

对面试官可这样表述：语料为可控本地笔记，规模用于验证 Agent 循环与评测体系；方法（混合检索、引用门禁、Workflow 对照）可迁移到更大文献库，但当前数字对应本库配置。

### RAG 扩写要点
库变大后，top-k 与 rerank 的收益通常比「小库打满」时更明显。保持词法/向量/混合三路同题对比，并固定 k。引用格式与拒答策略不随库增大而放松，否则幻觉引用更难发现。
