# 实验室问答系统设计笔记

## 目标用户与任务

面向实验室成员查阅内部笔记与方法说明：询问概念定义、工程约束、评测指标含义，以及「库里有没有某类信息」。不承担开放域网页搜索，不回答库外机密（密码、薪资、未收录设备信息）。

## 成功标准

可回答问题：答案含可验证 chunk 引用，且人工抽查大致被片段支持。不可回答问题：明确拒答，不编造。算术与闲聊：不误走文献检索。延迟与步数可报告，便于迭代。

## 非目标

不宣称已对接生产向量数据库集群；不做多模态论文图表理解；不把 ChatUI 壳当成 Agent 能力。实习作品的重点是 Agent 循环、检索对照、引用治理与评测闭环。

## 模块划分

文档层：Markdown 笔记与切分索引。检索层：词法/向量/混合/可选 rerank。决策层：手写 ReAct 或固定 Workflow。治理层：引用门禁、拒答、超时重试。评测层：金标与报告。服务层：可选 FastAPI。

## 迭代顺序建议

先打通单轮检索问答与引用；再上手写 ReAct 与工具；再补混合检索与评测；再做 Workflow 对照与 API。每一步留下可引用的数字与 bad case，而不是最后一次性包装。

## 风险清单

提示注入（文档内恶意指令）、串话、假引用、小库指标饱和被误读为通用 SOTA、密钥泄漏进仓库。对应缓解：Observation 当数据、每请求隔离 memory、引用查库、报告写清规模、.env 不提交。

## 扩库原则

增加与主题相关的方法说明；保持文风为学习笔记而非复制论文全文；每次扩库后 ingest 与抽查金标；简历数字与最新报告一致。

## 面试一分钟版

我做的是实验室文献笔记问答 Agent：模型决定是否检索与改写，答案必须带库内引用，证据不足则拒答。检索上对比了词法、向量与混合，并做了固定 Workflow 对照。评测拆开看工具选择、引用与拒答，而不是一个准确率打天下。

## 数据与隐私

实验室笔记可能含未公开实验设置。本地索引默认不出网；若使用云端 LLM，提示词中的片段等于离开本机。可对敏感节做脱敏或不入库。密钥与账号信息禁止写入 docs。

## 与论文 PDF 的差别

真实论文 PDF 需要解析、去页眉页脚、处理双栏与公式。本项目用 Markdown 笔记降低解析噪声，把时间留给 Agent 与评测。若实习岗位强调 PDF 管道，可在后续增量，而不要在方法未稳时先上重解析。

## 演示脚本

准备三题：算术、可引用事实、应拒答。每题独立 memory。能当场打开 trace 与报告路径，比只念简历字弹更有用。
