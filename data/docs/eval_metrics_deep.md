# 检索与端到端指标详解（学习笔记）

## Recall@k

相关文档集合与前 k 个返回结果的交集是否非空（或按集合比例）。实习报告里写清 k 与金标题数。小库易饱和时，补充分题型分析比只报 1.00 更有信息量。

## MRR

第一个相关结果排名的倒数平均。对「第一条就该对」的场景敏感。可与 Recall@k 一起看：Recall 高但 MRR 低说明相关结果靠后。

## 工具选择准确率

按题型标注 should_search / expect_tools。该搜未搜、不该搜却搜，都算错。算术题未调计算器、闲聊误检索，是常见扣分点，也能体现 Agent 相对固定流水线的价值。

## 合法引用率

可答题且需要检索的样本中，答案含至少一个库内真实 chunk_id 的比例。它不是忠实度。忠实度需要抽查语义支持关系。

## 拒答 F1

以应拒答为正类，计算 Precision、Recall、F1。只报准确率会掩盖「从不拒答」的系统。

## 延迟与步数

平均延迟、P95、平均步数反映成本。Workflow 与 Agent 对照时，这些往往比成功率更能说明取舍。Token 若估算需标明。

## 报告元数据

模型名、题数、检索模式、是否 rerank、切分参数、语料文件数与 chunk 数、时间戳。缺元数据的数字无法上简历。

## 常见误读

把引用率当 faithfulness；把小库饱和当大规模检索 SOTA；把 estimated token 当官方用量；把单次 Demo 成功当评测。

## 置信区间与小题数

题数较少时，成功率差几个点可能是噪声。报告题数，勿夸大微小差异。扩题时应保持题型比例，避免只加「简单必中」题抬高平均分。

## 分题型报表

按 proper_noun / synonym / refuse / calc / chitchat 分组看工具与答案指标，能直接指导改提示或改检索，而不是只盯总平均。
