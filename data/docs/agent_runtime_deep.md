# Agent Runtime 工程细节（学习笔记）

## 主循环结构

初始化 messages（system + 历史 + 用户）-> 调用 LLM（可带 tools）-> 若有 tool_call 则执行并回灌 Observation -> 否则进入最终答案路径 -> 引用门禁与停止。每步写入 trace。

## 重复调用熔断

对「工具名+参数」计数，超过阈值则停止或强制要求给出最终答案。防止模型在同一 ERROR 上死磕。

## 引用重试

门禁失败时追加一条用户侧校验提示，允许再生成一次；仍失败则系统拒答收尾。重试次数要有上限。

## 与 Workflow 嵌入

可将 Runtime 包在 Workflow 的某个节点内，外层仍控超时与权限。也可以完全分开：文献题走 Runtime，简单题走规则。

## 测试策略

单元：引用抽取正则、拒答词表、工具参数校验。集成：ingest 后 search 命中。端到端：金标跑批。回归：bad case 列表。

## 日志脱敏

不记录 API Key、不默认记录完整隐私文档。trace 可存参数摘要与 chunk_id，正文长度受控。

## 失败注入

人为让工具返回 ERROR、空 hits、非法 JSON，观察 Agent 是否受控退出。把结果写进故障类型统计，而不是只测 happy path。

## 交付物

可运行的仓库、评测报告、bad case 笔记、简历上能指到代码与数字的字弹。这比再堆一个框架依赖更符合实习考察。

## 并发与资源

本地 embedding 与 cross-encoder 占 CPU/内存；多请求并行时注意模型加载单例与锁。API 超时要覆盖「检索+多轮 LLM」最坏路径，避免网关先断。

## 版本冻结

对外展示或发布报告前冻结：模型名、索引、报告文件。临时改提示却用旧数字，会造成口径不一致。
